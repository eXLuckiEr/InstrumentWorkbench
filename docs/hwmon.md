# Плагин «Датчики Linux (SSH)» (`plugins/device/hwmon`)

Читает датчики Linux-устройства (проверено на задумке для OpenBMC, bash 5.x) по SSH и рисует сетку маленьких графиков.
**На устройстве ничего не устанавливается и не записывается на диск.**

## Как это работает

1. Приложение подключается по SSH и запускает на устройстве один `bash`-приёмник (команда `remoteCommand`, её подставляет плагин).
2. Через stdin приложение отправляет скрипт (`<длина>\n<скрипт>`), он живёт только в памяти процесса.
3. Скрипт один раз выполняет команды из настроек (версии FPGA и BMC) и печатает их вывод, потом в цикле читает файлы датчиков
   встроенной командой `read` (без запуска процессов), ставит метку времени из `$EPOCHREALTIME` и ждёт до следующего «тика»
   (период не уплывает). Остановка: строка `STOP`, при обрыве связи процесс умирает вместе с терминалом.

Строки от устройства (через табуляцию): `H` (готов), `I имя текст`, `E сообщение`, `L строка метка` (по одной на плитку, до `R`), `R число период_мкс`, `S метка_мкс v1 v2 …`.

## Подключение

Роль `stream`: выберите транспорт «SSH shell» (плагин `endpoint/sshshell`), `remoteCommand` подставится сам. Нужен `bash` 5 на устройстве.

## Настройки (кнопка «Настройки»)

* **Датчики**, по строке: `имя | файл | делитель | единицы`. Делитель и единицы не обязательны. В пути можно писать `*`
  (`/sys/bus/i2c/devices/13-0048/hwmon/hwmon*/curr1_input`): номера `hwmon` меняются между загрузками. До 32 датчиков.
* **Команды после подключения**, по строке: `имя | команда`. Выполняются один раз, вывод показывается вверху окна.
  По умолчанию: `FPGA` читает `/sys/kernel/debug/fpga-version/version.0`, `BMC` читает `PRETTY_NAME` и `VERSION_ID` из `/etc/os-release`.
* **Период** опроса, 20…2000 мс (по умолчанию 100).
* **Точное время** (галочка, по умолчанию включена): устройство ставит метки из `$EPOCHREALTIME` (bash 5) и держит период без
  дрейфа. Без галочки — простой режим: достаточно bash 4, фиксированная пауза между отсчётами, метки ставит приложение при
  получении (для отладки обычно хватает; реальный период чуть больше на время чтения). В протоколе метка `-`.

«Применить» сохраняет настройки (QSettings, группа `hwmon`) и перезапускает скрипт на устройстве без переподключения.

## График и значения

У каждого датчика плитка: имя, последнее значение и график. Двойной щелчок открывает большой график. Общий интервал (10 с … 15 мин) и пауза.
Если чтение датчика на отсчёте не удалось, график повторяет прошлое значение, шкала времени остаётся ровной.

## Тест

`tools/hwmoncore_test.cpp` проверяет разбор настроек, строки протокола и запускает сгенерированный скрипт настоящим `bash` 5 на
поддельных файлах (период, метки времени, экранирование, STOP). Работает в CI.

## Маски, текстовые плитки и пороги

Строка списка датчиков: `имя | файл | делитель | единицы | опции`. Опции (через пробел, все необязательны):

* `min=N`, `max=N`: плитка и значение краснеют, когда число вышло за пределы.
* `text`: состояние или флаг (в debugfs часто лежит `OK`, `0x3F`, режим). Показывается строка как есть, без графика;
  при изменении плитка на доли секунды подсвечивается. `expect=ЗНАЧЕНИЕ`: красная, если значение отличается.
* **Маска**: `{}` в имени и `*`/`?` в пути дают плитку на каждый подошедший файл, например
  `zone {} | /sys/class/thermal/thermal_zone*/temp | 1000 | °C | max=85` → плитки `zone thermal_zone0/temp`, … В `{}`
  подставляется часть пути, начиная с первого компонента с `*`. Без `{}` берётся первый найденный файл, как раньше.
  Всего не больше 32 плиток; лишние отбрасываются.

Устройство само присылает список найденных файлов (`L def метка`) перед `R`, плитки строятся по нему. До подключения
маска показывается одной плиткой.

## Пресеты

Набор «датчики + команды версий + период + режим времени» можно сохранять и переиспользовать для других устройств.
В панели «Настройки» сверху:

* **Выпадающий список «Пресет»**: встроенные (OpenBMC с токами, «Linux: температуры и частота CPU», «Linux: батарея»,
  «Пустой») и ваши сохранённые. Выбор пресета только заполняет редакторы; в работу он идёт после «Применить».
* **«Сохранить как…»** пишет JSON-файл (по умолчанию в `hwmon-presets` в папке данных приложения, она же показывается
  в списке). Файл можно отправить коллеге или положить в репозиторий. Некорректный набор (ошибка в списках) не сохраняется.
* **«Открыть…»** загружает файл из любого места; файл проверяется так же, как при «Применить».

Формат файла:

```json
{
  "format": "iwp-hwmon-preset", "version": 1,
  "name": "OpenBMC: токи", "description": "…",
  "periodMs": 100, "precise": true,
  "sensors": "curr1 | /sys/bus/i2c/devices/13-0048/hwmon/hwmon*/curr1_input | 1 | mA\n…",
  "info": "FPGA | cat /sys/kernel/debug/fpga-version/version.0\n…"
}
```

Списки хранятся как тот же текст, что вы правите в редакторах (с комментариями). Встроенные пресеты лежат в
`hwmoncore.h` (`builtinPresets()`), их корректность проверяет `hwmoncore_test`.
